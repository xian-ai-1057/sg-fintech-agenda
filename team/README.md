# SFF 團隊共編：自己的電腦部署

這是獨立 feature branch 的輕量版本。公開 GitHub Pages 仍使用原本 index.html；共編服務在你自己的電腦啟動後，於同一個網址提供 `/` 原議程、`/team/` 團隊畫布。GitHub Pages 本身不會執行 Python 或保存共編資料，所以純靜態部署不顯示此共編入口；只有自架服務會啟用首頁按鈕。

## 需求與啟動

- macOS、Windows 或 Linux，Python 3.10 以上。共編服務只使用 Python 標準函式庫，不需要 pip 安裝、Node、API key、LLM、雲端資料庫或 ChatGPT 帳號。
- 解壓完整專案，開啟終端機並切換到專案資料夾。
- 首次由擁有者在自己的電腦執行：

```sh
python3 -m team.server --setup
```

依隱藏輸入提示設定至少 12 字元的管理員密碼。沒有預設管理員密碼，也不會讓第一個開網頁的人自動當管理員。

```sh
python3 -m team.server
```

Windows 若沒有 `python3`，改用 `py -3`（例如 `py -3 -m team.server`）。開啟 http://127.0.0.1:8766/ ，先看到原本行事曆；按「共編行事曆」進入同站 `/team/`，再按管理員登入。共編頁也有「原本行事曆」返回入口。停止服務在終端機按 Ctrl+C。重新啟動使用相同指令，選擇紀錄會保留。

## 邀請同事與管理

1. 管理員登入後產生團隊邀請連結，手動傳給受邀同事。這會開放新成員加入。
2. 同事以暱稱加入，選擇各活動。每個人只能改自己的選擇；管理員可改所有人的選擇及撤銷成員。
3. 畫布依新加坡／台北時間顯示三天行程，選擇會自動同步，時間重疊只是提醒，不阻止選取。
4. 全員加入後可「停止加入」。重新產生邀請會使舊邀請失效，但不會登出既有成員；撤銷特定成員才會立即使該成員所有登入失效。
5. 撤銷成員的歷史選擇仍保留在資料庫，但不顯示於活躍團隊畫布。重新加入屬於新身分。

### 這個簡單方案的安全界線

- 持有邀請連結者可以取暱稱加入，連結可以被轉傳，暱稱不是經驗證的真實身分。不是逐封 email 驗證的邀請制。
- 被撤銷的人若仍持有有效邀請，可換瀏覽器／暱稱重新加入；要防止此情況，請同時停止加入或更新邀請。
- 任何有效成員可讀取團隊暱稱、選擇及匯出紀錄；請只邀請應該看到這些資料的人。
- 登入憑證保存在瀏覽器分頁 sessionStorage，最長 7 天有效。關閉分頁可能需要重新加入／登入；暱稱重複時請由管理員撤銷舊身分後重新加入。沒有密碼重設／身分復原郵件。
- 管理員密碼以 PBKDF2 雜湊儲存，邀請與成員 token 只存 SHA-256 雜湊。伺服器不會記錄網址或密碼內容。
- 所有寫入都經伺服器授權並用 SQLite 交易檢查，不是只靠前端按鈕隱藏。

## 讓同事連線

預設只接受本機連線，不會開防火牆或改網路設定。若你確定使用可信任的同一內網，可自行綁定內網介面，並明確允許瀏覽器使用的位址。將範例 IP 換成你電腦的內網 IP：

```sh
python3 -m team.server --host 0.0.0.0 --origin http://192.168.1.20:8766 --origin http://127.0.0.1:8766
```

首頁為 `http://192.168.1.20:8766/`，按「共編行事曆」前往共編；邀請連結則直接開啟共編頁。管理員應從該內網網址產生邀請，否則 localhost 連結只會指向同事自己的電腦。電腦必須保持開機、服務執行且網路可達；跨公司網路、VPN或防火牆是否允許，需依組織規定處理。

HTTP 會以未加密方式傳送密碼與憑證。不要直接把此開發型 Python HTTP 服務曝露到網際網路；對外部署需有 HTTPS 反向代理及適當網路防護，並使用 `--origin https://你的網域`。這次沒有配置外網、防火牆、DNS 或 TLS。反向代理須保留原 Host；目前登入速率限制以來源 IP 計算，代理部署需要自行評估多人共用 IP 的影響。

## 資料、匯出、備份與還原

- 預設 SQLite 在 `team-data/calendar.sqlite3`，含管理員雜湊、成員、選擇及登入憑證雜湊。`team-data/` 及 SQLite 檔已加入 `.gitignore`，不可推上公開 GitHub。
- JSON 匯出用於可讀活動分工紀錄，不包含 token／密碼雜湊，不能當作完整系統還原備份。請只分享給已授權成員。
- 使用 SQLite 安全備份（可在服務執行時做，目的檔必須不存在）：

```sh
python3 -m team.server --backup /你的私人備份位置/sff-backup.sqlite3
```

- 還原：先 Ctrl+C 停止全部服務；保留原 `team-data` 資料夾作為回復副本。將備份複製到一個新的私人資料夾，然後以 `python3 -m team.server --data /新的私人資料夾/sff-backup.sqlite3` 啟動。不要混用舊的 `-wal` / `-shm` 檔。
- 備份包含有效成員登入雜湊及管理員雜湊，必須保密。回復舊備份可能恢復舊邀請／撤銷前的成員狀態，請立即檢查成員並旋轉邀請。
- 可用 `--data` 指定自己的私有持久資料位置。每次啟動、備份要用同一個位置。
- 議程來源仍是根目錄 `agenda.csv`；更新後需重啟服務。資料不會自動外傳，不會自動發送通知。

## 與既有 AI 問答的關係

共編完全不使用 API key。原 `agent/` 是選用 AI 問答功能，仍有自己的安裝與金鑰要求；其 API key 過期不影響共編。這次没有自動重啟或重新部署 AI 服務。

## 測試

```sh
python3 -m unittest discover -s tests -p 'test_team.py' -v
```

原爬蟲測試需先依根目錄 requirements.txt 安裝 Selenium；共編不需此套件。
